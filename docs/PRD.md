# AI Panel Studio — 产品需求文档 (PRD)

**版本**: v1.0.0 | **日期**: 2026-06-26 | **状态**: MVP 设计完成

---

## 1. 产品定位与价值主张

**AI Panel Studio** 是一个 AI 圆桌讨论 Web 应用。用户只需输入一个话题，系统即可动态生成1名主持人 + 多名立场各异的 AI 专家，在演播厅中展开一场自然、非机械轮流的实时讨论。讨论过程中持续提炼共识与分歧并实时推送，最终由主持人给出自然语言总结。

**价值主张**：让任何人随时发起一场多视角、高质量的 AI 圆桌辩论，获得超越单一模型对话的思辨体验——不是"问 AI"，而是"看 AI 们辩论"。

---

## 2. 目标用户

- **思辨爱好者**：想从多角度审视一个话题（如"AI 是否应该开源"），观察不同立场专家的交锋。
- **学生与研究者**：利用圆桌讨论快速梳理争议性议题的正反观点。
- **内容创作者**：获取灵感素材——讨论 transcript 可直接作为文章/视频的参考框架。

MVP 阶段为开放访问模式，无需注册登录。

---

## 3. 核心用户故事

### US1 — 发起新讨论：生成嘉宾阵容 (P1)

用户输入讨论话题与期望专家人数（默认4人），系统调用大模型动态生成1名主持人 + 若干专家的角色阵容。每位嘉宾展示：姓名、职业/Title、立场简述、专属颜色标识。用户确认阵容后进入演播厅，或重新生成。

### US2 — 首页讨论列表与加入观察 (P1)

首页展示所有进行中的讨论列表（话题、嘉宾人数、当前轮次、开始时间）。用户可加入观察已有讨论，或发起新讨论。已结束的讨论标记为"已结束"并可查看回放。

### US3 — 演播厅实时讨论 (P1)

主持人自动开场→追问→串联→总结。专家根据上下文自主决定发言（补充/反驳/陈述），每次1–2句，禁止机械轮流。每位专家有独立状态小窗（待发言/准备发言/发言中/沉默中）。Transcript 实时更新，发言人用专属色块区分。共识与分歧实时提炼并推送。

### US4 — 多讨论并行与数据隔离 (P2)

系统支持最多10场讨论同时进行。每场讨论的数据以 discussion_id 严格隔离。用户可在多个浏览器标签页中同时观察不同讨论。

---

## 4. 功能需求列表

| 编号 | 需求描述 |
|------|---------|
| **FR-001** | 首页展示所有讨论列表（话题、嘉宾人数、当前轮次、开始时间、状态） |
| **FR-002** | 用户输入话题 + 专家人数（2–8人，默认4）。话题经后端内容审核服务检查，不合规拒绝创建。通过后 LLM 生成1名主持人+N名专家阵容 |
| **FR-003** | 每位嘉宾包含：姓名、职业/Title、立场、专属颜色标识。阵容保证观点多样性 |
| **FR-004** | 用户可确认阵容进入演播厅，或重新生成 |
| **FR-005** | 主持人自动执行：开场白、追问、串联、总结（自然语言，不显示JSON）。每轮评估是否收尾 + 30轮上限兜底强制结束。总结注明沉默专家 |
| **FR-006** | 专家根据 transcript 自主决定发言（补充/反驳/陈述），每次1–2句，禁止机械轮流 |
| **FR-007** | 专家独立状态小窗：待发言/准备发言/发言中/沉默中 + 公开关注点。不暴露思维链。连续多轮未发言自动标记"沉默中" |
| **FR-008** | Transcript 实时显示：发言人姓名+职业Title+色块+发言内容。不显示"举手"等内部事件 |
| **FR-009** | 讨论中持续提炼共识与分歧，SSE 实时推送。共识与分歧增量更新，非结束后一次性生成 |
| **FR-010** | 多讨论并行（≥10场），discussion_id 严格隔离。达上限时友好拒绝并显示讨论数/上限 |
| **FR-011** | SSE 实时推送 transcript、嘉宾状态、共识分歧更新。断线重连：快照 + Last-Event-ID 增量补拉 |
| **FR-012** | 用户可观察者身份加入任意进行中的讨论，实时查看 transcript 和共识面板 |
| **FR-013** | 已结束讨论保留完整 transcript 回放，可查看但不可交互 |

## 5. 关键约束

| 约束 | 说明 |
|------|------|
| **多讨论隔离** | 所有数据（状态/事件/transcript/共识/分歧）以 discussion_id 严格隔离。API 路由 `/api/discussions/{id}/...` 即隔离边界。删除讨论时级联清除所有关联数据 |
| **实时性** | SSE 推送所有实时更新。共识与分歧在讨论过程中不断更新，非结束才生成。每轮发言后 3s 内完成共识更新 |
| **安全** | LLM API Key 仅在后端环境变量，前端零暴露。所有 LLM 调用经后端代理。话题经内容审核服务检查。生产环境 HTTPS/WSS |
| **中文 UI** | 所有界面文案、提示、错误消息为简体中文 |
| **响应式** | 桌面 ≥1024px / 平板 768–1023px / 移动 <768px 三断点。演播厅各区域独立滚动 |

## 6. 边界情况确定方案

基于 `/speckit-clarify` 的5条澄清结论：

| # | 边界情况 | 确定方案 |
|---|---------|---------|
| 1 | **讨论结束触发** | 主持人每轮评估是否收尾 + 30 轮上限兜底强制结束。主持人总结中注明沉默专家 |
| 2 | **话题内容审核** | 后端集成内容审核服务检查话题，不合规则拒绝创建并返回具体拒绝原因 |
| 3 | **SSE 断线重连** | 快照 + 增量补拉：重连时先返回当前共识现状 + transcript 最后20条，再基于 Last-Event-ID 补发断线期间错过的增量事件，3秒内恢复 |
| 4 | **并行讨论达上限** | 友好拒绝 + 引导："当前讨论已满（N/N），请等待某场讨论结束后再发起"。首页实时显示讨论数/上限 |
| 5 | **沉默专家处理** | 标记"沉默中"状态但不阻断讨论流程。讨论结束总结中注明该专家未发表观点 |

### 其他边界情况

| 边界情况 | 处理方案 |
|---------|---------|
| 专家人数边界值（1或10） | FR-002 限制为 2–8 人，超出范围返回校验错误 |
| 话题为空 | 前端校验提示"请输入讨论话题"，不调用后端 |
| LLM 生成失败 | 用户收到友好错误提示（"嘉宾生成失败，请稍后重试"），允许重试 |
| 讨论删除 | 级联删除所有关联数据（transcript、共识、嘉宾信息） |

---

## 7. 假设与外部依赖

- 大模型 API（DeepSeek）可用且响应稳定，单次生成请求 5s 内返回
- 用户设备支持 SSE（所有现代浏览器均支持）
- 专家人数 2–8 人、默认4人是合理范围
- 色块颜色从预设9色调色板中分配，保证区分度
- MVP 无用户注册/登录，讨论为开放访问
- 内容审核 MVP 阶段为本地轻量实现（关键词+长度），预留第三方服务对接接口
